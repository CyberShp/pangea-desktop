# GitHub 在线更新

## 用户路径

已打包的 Windows x64 Desktop 在启动 15 秒后检查 `CyberShp/pangea-desktop` 的公开 Releases。设置 → 版本与升级提供“检查在线更新”；宿主菜单和 Ctrl+Shift+U 也可触发。正式版只检查 stable，测试版只检查 test。无更新时主动检查显示“已是最新版本”；后台网络失败不弹窗，设置页保留错误并可重试。

有更新时自动下载完整包，显示下载和校验两个独立进度。点击“安装并重启”后复用现有任务准入、签名助手提取、独立窗口握手、版本替换、健康确认和失败回滚。分析任务运行时拒绝安装，保留已校验包供稍后重试。不自动杀任务或自动安装。离线完整包和精确基线补丁导入继续可用。

## 发布契约

`create-signed-portable-package.mjs` 在 ZIP 同目录生成：

- `pangea-desktop-update.json`：schema、产品、通道、版本、Windows x64、最低源版本、锁定组件、完整包名/字节数/SHA-256。
- `pangea-desktop-update.json.sig`：使用现有 Ed25519 私钥对清单原始字节签名。

Release 工作流先创建 draft 并上传 ZIP、哈希、在线清单及签名和现有补丁附件，再取消 draft。客户端锁定具体 Release 的 tag/附件，不使用滚动 latest 下载链接。客户端验证清单签名、大小和哈希后，继续验证 ZIP 内部签名及全部文件；在线版本与内部版本必须一致。

下载使用 Electron 网络会话以沿用系统代理，允许 HTTPS GitHub 及其附件域名重定向；60 秒无数据中止。部分下载失败删除临时文件，重新检查可重试。首次实现不恢复上次进程的下载进度，重启会重新检查下载；不添加客户端 Token。

旧版客户端没有此入口，首次需使用原离线导入方式升级到包含本功能的版本。历史 Release 若没有在线清单和签名，客户端明确提示不能在线更新，可离线导入；不会绕过签名或静默降级到较旧 Release。

## 验证边界

`online-update-integration.test.ts` 调用真实签名打包脚本，模拟 GitHub HTTP 响应，通过真实下载写盘、清单签名、ZIP 验签、助手提取直到生成含健康标记的安装计划；仅 Electron、Windows 助手启动及任务准入为模拟。覆盖运行任务拒绝安装、助手启动失败解锁、重复检查/导入和无更新/网络错误。

`github-update.test.ts` 覆盖通道隔离、分页、重定向、签名篡改、最低版本、截断/超长/损坏包、HTTP 错误、取消及超时。插件设置页测试覆盖按钮 IPC、下载/校验、已最新与重试。

Linux 开发环境不能验证真实 Windows 替换、GUI 重启或回滚；现有 Windows CI 保留这部分回归。本次不触发 Release 发布。正式端到端验收需两个含新清单的版本：旧版本启动 → 获取新版 → 下载校验 → 空闲时安装 → 新版本健康确认；另需验证活动任务阻止安装与失败回滚。

## 公司代理与网络排障

宿主菜单 Harness → 在线更新网络设置，或在线更新错误卡片的同名按钮，可配置更新专用代理。地址留空沿用系统代理/PAC；也可填写 `http://主机:端口` 并单独输入账号密码，或填写 `http://工号:密码@主机:端口`。URL 中的特殊字符必须百分号编码。没有预设公司域名。

保存并检查更新会立即使用新配置。仅代理地址与账号写入用户配置；密码仅在本次进程内使用，重启后需要重新输入。留空密码保存会清除现有密码。更新进行中禁止修改网络配置。

证书校验默认开启。“本次运行跳过更新服务器证书校验（排障）”仅用于更新专用内存会话的允许域名，重启恢复默认；不会修改 Git、Node、Agent 或页面的全局 TLS 设置。即使开启，清单 Ed25519 签名、安装包大小/SHA-256 和内部签名验证仍强制执行。

传输使用 Electron ClientRequest 的代理认证挑战，仅向配置的代理主机与端口提供凭据，不向源站 401 或其他代理提供公司密码。每次更新结束清理连接及认证缓存。逐跳校验 HTTPS 域名白名单，安装包以有背压的流写盘，失败删除部分文件。

错误显示查询版本、下载更新清单、下载清单签名或下载安装包阶段，以及失败域名。407 提示代理认证，504 提示网关超时，403 区分已知 API 限额耗尽与一般拒绝。不会显示公司网关 HTML、代理密码或下载签名查询参数。

验收：先在含本改动的 Windows 包中打开网络设置，填写可用代理和凭据，保存并检查；确认查询、清单、签名、ZIP 下载与验签完成。分别验证错误密码、证书失败、网关 504、重启后密码和证书排障选项清除。开发机的模拟传输测试不代表公司 NTLM/Basic 代理或 Windows 原生 TLS 已通过实机验证。
