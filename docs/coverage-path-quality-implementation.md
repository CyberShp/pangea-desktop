# 覆盖率分析：范围、业务路径与用例粒度实施方案

## 基线与交付

2026-09-09，目标分支 `feat/module-analysis-five-stages`。
基线：pangea-agent `07006f5`、dsh-pangea `40ae41b`、pangea-desktop `2756cc2`。
先在隔离分支开发，验证后快进集成分支，更新 Desktop 精确锁定并产生 Windows 测试包。
用户验收内网真实模块；开发和自动化验证仅使用合成数据。

## 已验证问题

1. 覆盖率阶段 02 仅按缺口分组，没有先建立目标业务入口/路径目录，容易将多个流程压成一个分析组。
2. 标题加 flow_id 即可通过原投影检查；前端读取 mainline_steps，因此出现空步骤页面。
3. 同一用例可关联多个 gap_id，但未区分共用分析、自然跨模块路径和多个独立验证目标。
4. coverage-page 返回全报告缺口，没有目标范围处置视图；target 是语义目标，不能由关键词或文件名前缀解释。
5. 界面突出关联风险和用例数量，不能证明缺口定位、范围和测试设计完整。

## 授权和职责

保留五阶段、一次独立复核、现有 Run 生命周期。不给 Python 增加语义裁决权。
不以数量、字数、关键字判断质量，不增加失败重试或自动降级模式。
Producer 决定流程划分、耦合关系、范围、可达性和用例粒度；Reviewer 独立复核这些结论。
Python 只按当前 Run 的原始缺口 ID 合并显式分析记录、分页和统计，记录引用/结构问题。
可读但缺字段的分析结果保留并提示，不能因新增提示停止 Run、否决语义或替 Agent 改写。
用户已授权本方案开发；本次不引入新的语义门禁。

## 语义模型

- 缺口：原始函数、行、分支执行证据，保留 source/file_path/kind/raw/coverage_status/gap_id。
- 分析组：降低重复阅读的工作组织，不等于一个流程或一条用例。
- 业务流程：独立外部入口/业务目标；主干和分支表达相关行为路径。
- 用例：可独立执行与判定的验证场景，允许自然经过多个函数和模块。
- 报告范围、目标业务范围、源码读取范围分别记录。读取依赖不扩大补测目标。

## 五阶段改动

### 01 输入与定位

在现有输入与范围文档声明报告范围、目标行为边界、源码版本与证据限制。
先识别目标的入口、配置、运行时接线及耦合的状态/资源，再按需冻结源码。
全量报告不意味着全量分析；空代码范围不意味着全仓库都在补测范围。
保留输入和原始 ID；先分页读取，不把全量 JSON 放入上下文。

### 02 轻量业务盘点与缺口整理

在现有缺口台账里维护两张相关索引：业务路径目录、缺口处置。
路径目录包含外部入口、业务目标、正常/拒绝/异常/恢复等相关路径及 FLOW/BRANCH ID。
从入口向实现、从缺口向入口双向核对；不预先完成全部深度分析，也不固定流程数。
模块分析与覆盖率分析共用流程划分原则。
每个 gap 按证据记录 in_scope/out_of_scope/unresolved；未记录状态由展示层称为 unclassified。
范围外须有理由，范围内的共享函数须说明相关调用/状态/资源影响链；同文件或同调用链本身不足以纳入。
有范围外和待确认项时完整保留，不能按已完成补测统计。大报告按页推进、保存游标。

### 03 路径分析与独立用例

每个纳入路径连续完成接线、分支条件、状态/资源、保护、异常传播、外部结果和证据。
正文仍是覆盖缺口分析.md；业务流程投影必须包含实际主干与相关分支，空内容仅作为待补齐草稿。
用例有单一验证目标、可确认的初始状态、主要触发、可区分结果、独立观测及恢复。
不同关键参数/预期路径独立成例，可共享准备说明；不将多个独立场景写成连续步骤。
真实耦合场景可以跨模块；前置认证可以保留为准备；共享函数不能把所有调用者场景合成一个测试。
不限步骤数量，不要求一函数一用例，不穷举所有内部组合，不按功能名称设置禁配清单。
用例投影补 verification_goal、linked_flow_ids、linked_branch_ids、linked_gap_ids；已有字段继续使用。
两种 Skill 使用同一份受版本控制的规则内容（冻结包各自自包含），防止粒度定义不同。

### 04 复核与定向修订

检查目标入口/路径是否遗漏、范围外是否有据、共享与耦合场景是否过度扩大或被遗漏。
检查步骤是否实际存在、缺口是否能追到路径、用例是否混入独立目标或未真正构造所称路径。
依据源码判定，不以函数关联数作为补测设计完成证明。
仍由原 Producer 定向修改原文，现有 Reviewer 复查，不新增审核轮次机制。

### 05 交付

现有完整报告包含路径目录及分析限制，分别报告输入事实、范围处置、分析与用例设计状态。
一个用例关联缺口只表示设计追溯；未执行和复测不称为覆盖率提升。
旧 Run 读取自己的冻结版本与产物，不迁移、不改写、不用新 Skill 重新验收。

## 数据接口与展示

coverage_gaps 中增加 scope_status、scope_reason、scope_evidence_ids、linked_flow_ids、linked_branch_ids。
缺少或无效的范围声明显示未判定，不能默认视为范围内或范围外。
coverage-page 从当前投影按 gap_id 读取显式注释，原始覆盖字段始终来自冻结 combined.json。
未知/重复 ID、原始事实不一致及缺少依据作为 traceability_warnings；不静默选择冲突结论。
返回全输入 scope_summary（total/in_scope/out_of_scope/unresolved/unclassified/designed_in_scope），以及筛选后的 total/items/next_cursor。
新增 --scope-status、--flow-id、--query 只筛选显式字段，不做业务含义推断。
伴随插件通过绑定当前 task/run 的只读 coverage-page 请求提供真实分页；页面显示未发布分析的原始缺口。
缺口页显示目标、各范围数量、依据、路径、用例和原始状态，不能把未判定项藏掉。
流程页显示实际主干/分支与关联缺口；无步骤明确标为待补齐，不以空流程作为已分析结果。
用例页展示验证目标和关联流程/分支/缺口；无风险关联不再自动标成基础验证。
新字段缺失的旧结果明确显示未记录，不猜测填充语义。

## 确定性检查及误拦边界

新增检查只产生可追溯提示：流程缺步骤、引用不存在、缺口记录不全、范围声明缺依据。
草稿只有名称允许发布；直线流程允许无分支；端到端用例允许关联多个流程。
内容未补齐时 UI 显示待补齐，交付仍如实呈现未决，不将结构提示冒充 Reviewer 结论。
不对正文含义、拆分数量或场景可达性作自动判断。

## 实施文件与顺序

1. pangea-agent：coverage_input.py、CLI、两个 Skill 的步骤/共享参考/模板，增加独立于门禁的机械追溯提示。
2. dsh-pangea companion：只读分页路由、client 源码和生成 lib、流程与用例追溯、相应测试。
3. Desktop：持久合成 fixture/回归脚本、构建入口验证、组件锁定、测试构建触发。
不新增第三方依赖。设计文档消费空索引问题另行跟踪，避免本次扩大为资产系统重构。

## 验证

自动化：原始事实不可被投影覆盖、稳定分页 ID、范围计数守恒、范围外/未判定分离、同文件混合归属、重复/未知 ID 提示、跨流程合法用例、空步骤草稿、旧结果可读、查询失败不写成无缺口。
界面：真实分页、筛选、目标与范围计数、草稿待补齐提示、主干分支展示、用例互相追溯、当前 Run 绑定。
合成源码：多个外部入口，TLS/认证共享状态和清理函数、独立非 TLS 路径、合法/非法参数与异常恢复，覆盖报告近全零。
实际 Agent 前向试用：仅提供 Skill、目标和原始 fixture，不提供预期答案；检查行为路径、耦合边界与用例粒度。与宿主真实独立复核/内网模型验收分开报告。
最后跑 Windows 组装、成品 Harness/分析启动与签名打包。构建通过不代表真实内网分析质量通过。
