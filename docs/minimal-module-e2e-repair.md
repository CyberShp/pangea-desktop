## 已复现与方案

官方 test.79 首次启动分析被 Companion 的 codetalks-skill 1.4.0 精确校验拒绝，打包 Agent 实际为 1.4.1。修正后，同模型在 82 行会话模块及两工作表中文覆盖率文件上跑完五阶段，但发现以下问题：

- 流程文档使用普通 json 代码块配 pangea-flow 标题，且投影缺 document_path，正式页面只有名称。修复两套 Skill 的精确格式示例和发布后读取投影的核对方法；不从自由正文猜流程。
- 用例章节内的“前置：”被读取器当作另一字段，导致后续步骤丢失。明确 Markdown 章节边界优先于紧凑字段解析，并补齐标题层级、粗体元数据读取。
- 不同错误路径合并、准备步骤 Oracle 与源码矛盾，却自审 PASS。改为逐例核对初态、准备操作真实返回、主要触发、实际分支和剩余状态；不同预期独立成例。
- 同文件独立端点被扩为补测目标。要求先查目标影响链，区分原始路径缺失与冻结源码候选可读性；待确认范围保留台账，不生成正式占位用例。
- 上游 request.md 将 source_scope 文件列表标成“用户范围”，容易与目标业务范围混淆。改为“源码冻结范围”，覆盖率请求明确按 target 及实际影响链限定补测。
