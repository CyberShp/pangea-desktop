# 便携版升级目录占用恢复

适用：Desktop 已导入并验证补丁，重启升级时提示安装目录访问被拒绝，随后原版重新启动。

## 中断事务与重复升级保护

新助手在安装目录的父目录保存 `.pangea-update-<安装路径哈希>.json` 事务记录，并使用同名 `.lock` 文件的系统独占句柄防止两个独立升级／恢复进程同时修改同一安装目录。锁覆盖退出旧版、恢复、重建、切换、健康检查与回滚；进程异常退出后系统释放句柄。锁文件保留是正常行为，不代表一直被锁住，不应通过删除锁文件来尝试解锁。

每次关键目录移动之前，先原子写入并刷盘保存意图。事务包含规范化安装路径、独立 `p-up-N` 工作目录、当前用户、事务标识、原版／目标版组件清单哈希与版本、工作进程身份及配置快照状态。恢复验证记录、工作目录归属和磁盘实际身份，不依赖已死亡进程内的标志。安装目录、工作目录、事务文件中的链接、错误身份、既有未知目标或不明文件一律阻断，不覆盖未知文件。

- 原目录尚未移动时中断：保留原版，将事务标为已恢复；候选文件保留。
- 原目录已移到 `p-up-N\old`、安装路径暂时不存在：从已核验备份恢复安装路径。
- 新版已启用但尚未提交：将新版移到空的 `p-up-N\failed` 保留其数据，再恢复旧版和已保存的外部 profile 配置。
- 新版健康确认且事务已提交：保持新版，清理异常不得回滚到旧版。
- 已恢复事务再次执行：只验证并启动当前旧版，不重放配置快照，以免覆盖恢复后的用户编辑。

恢复中断只恢复并启动相应版本，**不会同时继续应用新包**；恢复完成后可重新发起升级。安装路径暂时消失时，仍可从外置目录执行以下入口：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\pangea-update-recovery\resume-portable-update.ps1" -InstallRoot "D:\pangea-desktop" -TargetVersion "2.0.13" -RecoverOnly
```

入口复用已验证的完整包或补丁计划；恢复现有事务不要求包仍存在。普通重试则重新核验包大小、SHA-256、最低源版本 **2.1.8** 与补丁精确基线。可用 `-UserDataRoot` 指定自定义数据目录；默认尊重 `PANGEA_USER_DATA_DIR`，否则使用 `%APPDATA%\pangea-desktop`。旧助手未记录事务的历史故障，不能靠新版凭空确定哪一份目录属于有效备份。

正常成功只清理已确认的旧版目录。事务收据、配置快照以及失败候选目录保留供诊断和找回新产生的编辑，不自动递归清理。配置快照属于用户数据，应按本地数据处理，不随问题报告上传。没有新增系统启动项或后台常驻恢复服务。应用启动检查及升级入口使用同一事务状态；安装路径缺失时使用上述外置恢复入口。

工作台就绪默认等待 **300 秒**，继续显示剩余时间并核验 PID、版本和标记时间；计划可用 `startup_health_timeout_seconds` 显式指定 30–600 秒整数。没有该字段的旧计划也使用 300 秒。新版本超时仍回滚；原版本恢复启动超时只报告未确认，不强制结束仍在启动的原版进程。

`scripts/verify-portable-update-transactions.ps1` 在独立临时工程中，真实结束测试子进程覆盖候选完成、两次移动的意图／完成窗口、回滚移动窗口及提交完成；同时验证跨进程互斥、重复恢复、不覆盖未知文件／链接／错误身份、保留失败版本数据、终态不重放配置和最低源版本边界。测试可运行在 PowerShell 5.1；非 Windows 环境用标准目录改名替换 Windows 占用清理边界，因此真实 Windows 占用、CIM、ACL 与断电后的文件系统持久性仍由 Windows 集成验证负责。

## 2.x：TortoiseGit 缓存占用恢复

若日志出现 `directory handle: TGitCache ... policy=protected`，随后安装目录改名失败，说明当次升级器没有自动处理 TortoiseGit 的目录监视缓存。修正后的助手仅在以下条件全部满足时处理它：扫描证明它仍实际占用目标安装目录；同用户、同会话，且不是服务、关键进程或升级器祖先；程序路径与 HKLM `Software\TortoiseGit` 的 `CachePath` 注册值一致（检查 32/64 位视图）；文件版本资源的 `ProductName=TortoiseGit`、`OriginalFilename=TGitCache.exe`。名称相同但路径或产品信息不匹配的程序继续保留。

每次处理前重新检查占用、PID、启动时间、路径和保护策略。目录切换最多执行三轮清理；新出现的缓存进程必须在后续轮次独立验证，不能沿用旧 PID 的处理决定。清理和改名共用总预算（默认 90 秒，包含 30 秒改名等待及 60 秒清理预算），不会无限重启/结束缓存；Explorer 仍只处理一次。单个进程检查失败不再中断其余候选；最终错误显示受保护/未释放进程及 PID 或扫描失败原因，避免只有“访问被拒绝”。

历史 **2.0.7 → 2.0.13** 曾通过外置助手恢复升级。该升级源现已停止支持；已有中断事务仍可用上文 `-RecoverOnly` 恢复，不会继续应用新包。当前以 **2.1.8 → 2.1.9** 为例，对已导入并验证但升级失败的包，可将最新的 `resume-portable-update.ps1` 和 `apply-portable-update.ps1` 放在安装目录外，关闭 Desktop 后恢复原升级计划：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\pangea-update-recovery\resume-portable-update.ps1" -InstallRoot "D:\pangea-desktop" -TargetVersion "2.1.9"
```

恢复入口只复用 `%APPDATA%\pangea-desktop\updates` 中安装路径、目标版本和当前基线都匹配的已验证计划；保留原计划，新建独立恢复计划，重新检查包大小、SHA-256 及重建文件。它不修改已签名补丁或旧安装文件，不信任过期父进程 PID。`TargetVersion` 必须显式提供，不再默认历史 1.x 目标。新版助手只供本次恢复执行；成功安装后仍是计划指定的已签名目标包内容，外置脚本不会改写包内文件。

2026-09-17 的日志停在 `42% Preparing the new version`，没有 `indexing ... target files`。旧助手在补丁重建前移动整个安装目录；该阶段目录访问失败会立即中断。日志不能区分目录句柄占用和 ACL 权限问题。

## 修复行为

- 先从原安装目录读取未变更文件，在同级候选目录重建、校验并复制 `launch-root` 和 `local-skills`，最后才切换目录。
- 目录改名与占用清理共用默认 90 秒预算。记录源、目标、系统错误，并按下文的本机进程处理规则释放实际占用。
- 使用精确目录改名，拒绝已存在的目标，避免意外嵌套移动。每次备份使用独立名称，不删除之前失败留下的备份。
- 回滚失败也保存升级结果和备份位置；未恢复成功时保留候选目录及备份，不冒充恢复成功。
- 用户目录改用 Robocopy 复制，支持深层源码仓库路径，保留目录链接而不展开链接目标。任何复制失败都会中止切换，并在 `apply-update.log.copy-launch-root.log` 或 `apply-update.log.copy-local-skills.log` 保存完整系统错误。临时目录清理使用支持长路径、不会递归删除目录链接目标的 Windows `rd`。

## 最低支持版本

当前构建、补丁生成、发布校验、完整包／补丁导入与独立助手均以 **2.1.8** 为最低升级源版本。2.1.7 及更早版本不再使用当前脚本原地升级；应在独立目录安装完整包并保留原安装目录与用户数据。历史发布包不会被本次修改删除。

新版工作台先关闭任务入口，再检查运行、排队和收尾状态；准备失败会解除冻结。HTTP、RPC、直接执行器调用和资产队列共享同一入口保护。历史旧版 2.0.7 不具备这个接口，且已退出当前升级支持范围；对已有中断事务只执行恢复，不把历史恢复当作当前受支持的升级路径。

## 空间与用户数据

导入前检查用户数据所在盘的暂存空间；退出旧版后按新版展开体积、用户目录副本、配置快照、文件分配余量检查安装盘空间。安装目录中不在原包清单内、也不在 `launch-root`／`local-skills` 中的自建内容会阻止切换，并列出需要保留的位置。

复制、解压、哈希和目录清理在受监督的独立进程内执行；超时会结束该次操作的进程树并确认退出，无法确认时保留材料并停止切换。子进程只向自己的进度文件报告，由主升级器转发，不能把子进程退出误报为升级中断。

用户数据复制前停止已核验的后台写入者，检查数据目录占用，并对复制结果及切换前后的原目录多次比较内容与链接指纹。未知或受保护占用、复制期间修改均会阻断操作。这属于静止检查与内容复核，不是文件系统原子快照；升级期间外部程序不应重新开始修改这些目录。

## 验证

`scripts/verify-portable-update-locks.ps1` 在 Windows 上建立真实目录句柄，验证持续占用时原目录不变、短暂占用释放后成功、目标存在时拒绝覆盖，以及回滚改名保留文件内容。`verify-portable-patch-apply.ps1` 验证补丁重建及 Run/skill 保留。专用 Windows CI 运行两者，Linux 上的单元测试不能替代该验证。

`scripts/verify-portable-user-data.ps1` 另外验证超过 300 字符的仓库文件路径、Unicode/方括号文件名、空目录、目录链接、链接目标清理安全，以及文件被独占时拒绝继续升级并保留原数据。

## 本机占用进程处理

目录改名失败后，助手在独立、限时的本机扫描进程中检查实际文件/目录句柄（包括安装目录外的终端持有的当前目录）。扫描失败或权限不可见时，不把“未找到”视作“没有占用”，不调整权限，也不提权。底层系统句柄接口在不同 Windows 版本上可能不可用，此时安全退出并记录本机原因。

新版 Desktop 在拒绝运行中的分析会话后启动助手。助手趁 Desktop 尚未退出，记录其运行时子进程的 PID、启动时间及程序路径。实际持有安装目录、身份仍一致、同用户同会话且不属于系统服务的已记录子进程会自动结束。常见运行时与终端占用也自动清理，包括 `node`、`python/pythonw`、`cmd`、`powershell/pwsh`、`WindowsTerminal/OpenConsole`、`opencode`、`nga`、`codeagent/codeagentcli`、`claude`、`uv/uvx`，不再弹出确认清单。

每个结束动作前重新扫描占用，并核对 PID、启动时间、程序路径和安全分类；执行结束时持有同一个系统进程句柄，再次核验启动时间，避免 PID 复用导致误杀。先向有主窗口的进程发送关闭请求，最多等待 2 秒，再结束仍存活的进程；无主窗口的运行时直接结束，不逐个空等 2 秒。进度窗口与本机日志显示当前处理序号、进程名、PID 和结果。处理对象必须实际持有此安装目录或子路径的句柄，不按名称遍历并结束全机进程。

未记录归属的编辑器、未知程序、系统服务、关键进程、其他用户/会话以及升级助手与其祖先进程（下述 Windows Explorer 除外）保留保护。这些占用只写入日志和进度状态，不弹出阻塞对话框。清理后继续重试目录切换，仍失败则按既有超时退出并保留原版与回滚材料。

旧版恢复入口仍关闭自动归属清理：旧计划及已退出父进程不能证明残留进程身份。请同时更新两个恢复脚本；实际占用目录的上述运行时、终端与 Explorer 仍会自动清理。继续保留目录整体切换、健康检查与失败回滚。

Windows 回归 `verify-portable-handle-resolution.ps1` 覆盖外部终端的真实当前目录句柄、错误启动时间拒绝结束、服务/祖先/未知进程保护、无需确认释放多个进程并改名，以及真实子进程归属清理。`verify-portable-batch-cleanup.ps1` 另外用模拟系统边界验证 20 个进程零确认、完整运行时名单、身份变化、占用释放、服务/用户/会话/祖先保护和新出现进程不会混入当前清理批次；该策略回归也可在非 Windows 的 PowerShell 中执行。

## Explorer 占用恢复

仅处理实际持有安装目录句柄、同用户同会话、路径确认为 Windows\explorer.exe 的 Explorer。常规升级与旧版恢复入口均自动处理：先关闭指向安装目录的资源管理器窗口；仍占用时重新核验 PID 与启动时间后结束该进程，每次升级最多尝试一次。桌面和任务栏可能短暂消失，随后自动恢复。其他 Explorer 不按名字批量结束。

独立守护进程先完成启动握手，再允许处理 Explorer。升级成功、回滚或助手异常退出后，守护进程检查本会话桌面 Shell；只有尚未恢复时才启动 Explorer，避免重复启动。守护无法启动则中止该清理动作。

Windows CI 的 verify-explorer-recovery.ps1 验证 Explorer 身份策略及守护在正常完成、助手崩溃、取消和 PID 复用情况下的行为；使用独立测试子进程，不结束 CI 桌面。真实桌面闪退和恢复体验仍需在 Windows 交互会话验证。
