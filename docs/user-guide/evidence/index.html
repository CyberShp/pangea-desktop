案例 B · 区分预期拒绝与缺陷

先确认“应该失败”，再看是否按约定失败

冻结源码格式和校验错误均有明确拒绝分支。

原分析记录用例的预期结果

  • 认证返回非 0 错误码，key 解析阶段即中止
  • 日志包含 'Invalid key format' 或 'Invalid key checksum'

冻结源码认证结束通过回调通知。

回调是程序在操作结束时通知测试工具的结果。启动返回 0，不能单独说明最终认证通过。

编辑者判断

保留拒绝行为检查，补齐后再采纳到执行计划

代码明确拒绝非法输入，本条可作为异常输入用例。先拆开“前缀错误”和“CRC 错误”，补最终回调状态、日志和有效密钥恢复对照；没有相应测试工具时先暂不采纳到立即执行集合。

把原用例补成可以交给执行人员的步骤

下面是本指南的完善建议，尚未执行。SPDK 测试程序需要支持设置测试专用密钥、调用公开认证接口、持续处理完成事件，并记录最终回调。

补充项执行人员应拿到的内容
输入拆成两条：A 缺少 DHHC-1 前缀；B 前缀、长度与 base64 有效，只改变 CRC32 校验值。使用专用测试密钥。
有效对照同一环境与身份下，有效测试密钥能够完成认证，最终回调 status=0。
操作通过已经确认支持的测试入口设置异常密钥并发起认证；保持完成事件处理运行。分别保存启动返回值、最终回调状态和对应日志。
通过标准异常密钥最终认证失败；分别出现格式或校验日志；没有错误的成功认证结果。仅观察到启动返回 0 时继续等待完成通知。
失败与未完成异常密钥最终认证成功或进程崩溃，属于待调查失败。超出团队规定观察窗口仍无结果，先记录为未完成，再排除轮询未运行和连接不可达。
恢复换回有效测试密钥；按实际连接状态重新连接或重新认证，确认最终回调 status=0。
采纳条件输入构造、公开入口、完成通知和日志都有可用工具，团队确认通过标准后采纳。缺工具或入口时，记录需要补齐的部分。
