# 补丁升级进度与失败结果

点击“重启并升级”后，Desktop 先打开独立升级窗口，确认窗口已经显示才退出。窗口由同一份已签名更新脚本的独立 STA PowerShell 进程运行，复制、解压、校验和目录切换不会阻塞窗口的消息循环。

窗口显示目标版本、当前步骤、阶段进度、总耗时、本阶段耗时、最近进展及日志末尾，并提供打开日志、打开日志目录和复制诊断信息。阶段百分比不代表剩余时间；健康检查单独显示实际 150 秒超时预算。运行中可最小化，完成后可关闭。失败结果和回滚状态持续展示，不再自动消失。

## 交接与异常处理

- 每次导入使用独立 `import-XXXXXX` 目录；每次启动使用原子创建的 `run-XXXXXX` 目录，内部文件固定为 `apply-update.ps1`、`update-plan.json`、`healthy.json`，防止重试读取旧的就绪标记，也避免每个文件叠加长 UUID。
- 新宿主只启动支持 `PANGEA_UPDATE_MONITOR_PROTOCOL=1` 的已签名更新器；窗口真实显示后才写入 UI 就绪标记，工作进程完成准备后才回复主程序。
- 新计划要求主程序明确写入 `.continue` 才允许关闭 Desktop 和修改安装目录；超时或初始化失败写入 `.cancel`，迟到的工作进程不能继续升级。
- 旧宿主生成的计划不要求新增确认标记，但新版脚本仍强制等待可见窗口。手动恢复入口同样不等待已经退出的主程序确认。
- 工作进程原子写入 `.progress.json`。监视器检查 PID 和启动时间；异常退出显示“恢复状态未知”，不冒充已恢复。确认进程退出后重新读取终态，避免误报刚完成的升级。
- 失败结果区分安装目录未切换、原版本文件已恢复、回滚失败和状态未知。原版本文件恢复与工作台启动分开确认：显式从安装目录启动，记录 PID、启动日志及标准输出/错误，等待前端工作区就绪标记；核验版本、PID 和时间。提前退出显示退出码，150 秒超时显示“工作台就绪未确认”，每 5 秒更新进展；不强杀仍在启动的旧版本。日志和上次失败结果持续保留到下一次升级尝试。

## 路径与临时文件

- 安装目录旁原子预留 `p-up-1`、`p-up-2` 等短目录，内部 `new`、`old`、`failed` 分别存放候选版本、原版本备份和失败版本。遇到已存在目录跳到下一编号，不覆盖旧备份；仅在安全完成后清理自己的目录。
- 补丁基线复制、载荷提取、全量解压和逐文件大小/SHA256 校验统一通过 Win32 Unicode 扩展路径和文件句柄执行，兼容 Windows PowerShell 5.1，无须修改系统长路径设置。短名称与长路径支持同时保留。
- 诊断控制文件与手动恢复计划使用 `handles-1.json`、`explorer-1.json`、`resume-1.json` 等原子预留短名称。签名和文件完整性校验仍使用原有 SHA256。

## 回归验证

`test/portable-helper-handoff.test.ts` 验证主程序确认、窗口初始化失败、超时取消、非法就绪标记与旧协议拒绝。类型检查和 Electron 编译验证宿主集成。

`scripts/verify-portable-update-progress.ps1` 在 Windows PowerShell 5.1 中创建真实独立窗口，验证可见就绪、耗时刷新、阶段更新、失败留窗、异常进程退出、成功结果保留及目录改名。现有目录锁、补丁重建、用户目录和 Explorer 恢复回归继续运行。

`scripts/verify-portable-long-paths.ps1` 验证 221→261 字符边界、超过 350 字符的依赖复制/解压/校验、损坏与路径越界拒绝、短目录预留及切换回滚。`scripts/verify-portable-rollback-start.ps1` 使用隔离模拟程序验证启动工作目录、环境、日志参数、健康确认、退出码与超时，不接触用户工作台或配置。

Linux PowerShell 的语法和无界面状态测试不能替代 Windows 窗口验收。正式打包时必须包含更新后的 `build/apply-portable-update.ps1` 并重新签名，不能通过修改已签名 ZIP 交付。
