# 资产管理收尾修复与验证

本记录接续资产多任务验收及模型路由复核。修改在三个隔离源码工作区及自有 PANGEA Desktop Dev 实例中完成，尚未提交、推送或发布。

## 确定缺陷及修复

1. 方法论生成进入 `finalizing` 后，资产页面把任务误判为不再活跃，停止定时刷新，可能一直停留在收尾状态。将该状态纳入已有轮询；到 `completed` 或 `failed` 停止，页面隐藏时仍不轮询。
2. 测试用例页“关联风险”显示的是有风险关联的用例数量，容易被误读为风险数。改为“关联风险的用例”，保持计算逻辑。开发版实际 is_even 页面显示 10 条用例、5 条关联风险的用例；该 Run 的风险页为 3 条风险。
3. Skill 增加资产陈述到当前风险的推导要求：区分历史故障、设计意图与当前源码；核对当前操作、触发条件、传播路径；使用反例和等价输出检查；分清语言标准与目标实现条件。Judge 同样复核这些证据，同一 Agent 执行时如实称为自审。
4. 方法论 worker 增加补丁前后外部结果比较要求，历史材料证据不足时保留待核实条件。直启规则的 Skill 版本文案由 1.2.0 修正为实际要求的 1.3.0。

未增加 Python 语义判定、索引结构或模型配置体系。已冻结的 Run 和历史报告没有改写。

## 验证

- 轮询新增行为测试先复现缺少定时器，再验证 `finalizing` 可刷新到成功、失败两类终态并停止，隐藏页面不轮询。
- 资产插件测试 15/15、工作台插件测试 126/126 通过，前端构建完成。
- 前端及运行时规则已同步自有解包开发实例；重启后在浏览器确认新计数文案。
- 没有追加完整九步任务。使用真实 OpenCode ACP 默认模型 `opencode/big-pickle` 做两轮局部源码复核：第一轮五个短函数案例，第二轮仅复验其中两个数值案例。

## 模型语义复核尚未完全通过

第一轮正确排除 clamp 等价分支误报、`v % 2 == 0` 的溢出误报，识别除零及缓冲区越界，并对缺失封装实现保留待确认。但是解释错误地把 C17 当成强制二进制补码，并无条件声称 `abs(INT_MIN)` 不可表示。

补充标准版本与实现条件的通用规则后，第二轮仍有不严谨表述：给取余判断加入二进制补码假设、无条件推导 INT_MIN 为偶数，且未给绝对值可表示性加上实现条件。因此只记录分类方向改善，不能称为报告语义验收通过或模型质量问题已修复。正确复核应分别检查取余的除数和商可表示性，以及绝对值的数学结果是否可由返回类型表示，不能把一个表达式的结论扩大为整个运算符的无条件保证。

规则修改属于已落实的流程约束；两次提示词复核不足以证明真实九步报告稳定遵守。后续内网小模块验收应抽查资产到源码的因果证据及模型的标准依据，不因状态完成而跳过内容复核。
