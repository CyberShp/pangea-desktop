# 输入材料与画图会话修复

基线：test.78；Agent 4b041b9、插件 8a65443、Desktop b6a341e 对应本地等价树。

## 用户可验收行为

- 中文函数覆盖率表支持“特性 / 模块 / 代码 路径 / 函数名 / 是否覆盖 / 空列 / 覆盖次数”。多工作表、未知计数、冲突计数和缺路径记录有明确记录，不静默当作零命中或丢弃。
- 资产导入/重新解析与直接文件分析使用同一覆盖率解析器。新建分析可选择已解析覆盖率资产，直接冻结其 combined 结果；旧解析版本资产在新建任务时升级解析，原 Run 副本不变。
- “重新规范化”改为“重新解析原文件”。每次保留独立解析结果；失败保留旧结果。普通文档提取正文、表格和图片，不冒充语义分析。历史问题内容未变化保留审核；变化时保留旧成果与审核副本，并重新审核新内容。
- DOCX 保留段落/表格顺序与位置；附件随 Run 冻结。任务概览显示材料冻结版本、消费声明、引用范围和关联分析 ID，不把导入成功标成已使用。
- 五阶段流程 Markdown 可包含显式 pangea-flow 内容块。投影通过 document_path 引用；publish-stage 复制步骤和分支，Agent 不再维护第二份步骤。Step 03 未完成时可看已写步骤草稿。旧自由正文提供原文入口并标为暂未解析，不伪造步骤。
- 后台画图不会改变当前任务会话；“打开画图会话”统一激活会话并切换。后台 Job 输出独立显示，定时刷新，丢失的 Job 单独标为状态不可确认，已验证图产物仍可打开。
- 查询页显示原始查询参数和平台匹配结果，提供留档的重新获取。已进入下游分析时基于修正输入新建关联任务，保留原分析。

## 内网查询 Skill 对接边界

工作区不包含内网 coverage_query.py，不能在此修改/验证平台版本查找。Desktop 继续以参数数组分别传递 product 和 version，不写死产品前缀。

内网 Skill 应接受短版本或完整版本，使用平台实际版本目录/既有查找能力定位精确对象。不能在未知平台契约下拼接前缀，也不能从多个候选中随便选择。

combined 输出可附加 query_resolution：

```json
{
  "status": "matched",
  "product": "平台产品名",
  "version": "平台完整版本名",
  "version_id": "平台版本ID",
  "module": "平台模块名"
}
```

无法定位使用 status=not_found，多个候选使用 status=ambiguous，并带 message。宿主将这两类明确匹配失败作为 error，不继续冒充 no_data。matched 后确实无覆盖数据才能返回 no_data。旧 Skill 没有此字段仍可调用，但界面明确提示匹配结果未确认。

修正查询调用 runs coverage-refresh --data-root ... --run-id ... --query-file ...；由界面生成参数文件。仅限未进入下游分析的查询 Run，获取结果和参数保留在 inputs/coverage/acquisitions。正在运行的分析先停止，避免边读边换输入。宿主异常退出留下 acquisition.lock 时需先确认原查询进程已经结束，不能绕过并发保护。

## 验证范围

- verify-input-materials.py：真实 XLSX/DOCX 解析、中文表头、多表、未知/冲突、资产复用、冻结不变、重新解析失败保留结果、审核保留、附件冻结、两套 Skill 的流程字段读取、真实子进程查询参数与 no_data 刷新。
- verify-module-workflow.py：五阶段发布/恢复/交付及 Step 03 中途从 Markdown 发布步骤。
- verify-coverage-path-quality.py：原覆盖率范围与路径追溯回归。
- 插件 Node 测试包含流程草稿读取、材料消费展示、后台会话不抢占、画图状态/输出与丢失 Job 隔离。
- 本地 Linux 验证不代表 Windows 成品验收，也不代表内网查询平台或真实模型分析质量验收。

旧 Run 冻结的 Skill 不自动替换。新版发布约定只影响新任务；旧流程自由正文仍能打开，但不会被程序猜测为结构化主干步骤。
