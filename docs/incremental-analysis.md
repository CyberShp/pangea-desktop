# 已有 Run 的定向补充与增量分析

## 使用入口

在已完成或已停止的 source-first 分析任务概览中，点击“补充 / 增量分析”。
用例和风险详情也可以点击“补充这条结果”，自动选中对应原始记录。

- **定向补充**：填写本次要求，例如“只补充 TLS 断链后的资源释放与恢复场景”。
  可按需选择业务单元或已有记录，使用来源 Run 保存的源码和资料。
- **按变更文件分析**：先更新工作区中的源码仓库，再填写相对仓库的文件路径，每行一个。
  可填写修改、删除或原快照中未记录的文件；分析说明可选。此版本由用户指定文件，
  不自动发现 Git 提交差异。文件变化影响哪些业务路径，由 Planning 和 Reviewer 结合源码判断。

创建后会自动启动独立任务，继承来源任务的场景、模式、Provider 和模型配置。
新任务概览提供来源分析链接、本次要求和变更文件，报告同样说明来源和源码基线。

## 数据与执行边界

- 原任务、原 Run、冻结输入及结果均不写回。新任务不继承原会话、Job、attempt 或已接受结果身份。
- 选中记录使用 `action_id + record_id` 联合定位，避免不同单元重复编号串用。
- 父结果和资料冻结到新 Run，原记录仅作历史参考。父 Run 或活动资产后续不可用，
  已创建的新 Run 仍可恢复并读取自己的参考输入。
- 变更文件保存前后哈希、文本差异、删除及基线缺失状态。原快照没有该文件只能标为基线缺失，
  不能推断为新增文件。旧覆盖率明确保留为历史数据，不称为新版本实测结果。
- 父记录原文按索引分页读取，任务提示不逐条展开全部历史内容。
- Planner 只为本次补充目标或变化影响规划单元；复核和定向修正继续使用原 source-first 流程。
  新报告只交付本次新增或修订内容，不自动合并父 Run 全部成果。
- 正在运行的父 Run 需要先完成或停止。缺少冻结源码的历史 Run 会显示明确原因。
  若本次可分析源码已全部删除，需要将仍存在的受影响调用方加入文件范围。

## 验证

Agent 的 `verification/incremental_smoke.py` 使用真实 Graph、源码冻结和恢复接口，
覆盖来源不变、精确记录引用、文件差异、独立结果、父 Run 不可用后的恢复及资料读取。
Windows 打包脚本会在嵌入式 Python 和待打包 Agent 上运行同一验证。

Companion 增加 `incremental-analysis.test.mjs` 与 `incremental-client.test.mjs`，验证路由、
任务关联、创建/启动失败及跨工作区异步响应。`incremental-core.integration.mjs`
通过真实 Python CLI 串接工作台 options、task-derive、task-start 和新 Run 创建，
分别核对两种源码策略，以及父目录全部文件哈希和原任务保持不变。

跨仓测试需将 `PANGEA_PYTHON` 指向测试 Python，`PYTHONPATH` 指向 Agent 的 `src`，再运行：

```text
node --test --test-isolation=none --test-reporter=spec tests/incremental-core.integration.mjs
```

本轮本地验证结果：

- Companion 全量回归：382 项通过，9 项跳过；前端产物已重新生成并通过语法检查。
- Agent 增量验证：6 项通过；Desktop 原有源码快照、模块工作流、分析场景验证共 17 项通过。
- 跨仓真实 CLI 集成通过，包含定向补充和变更文件两种模式。
- 实际 React 组件经浏览器检查：模式切换、中文路径、精确记录选择和提交，以及窄窗口布局。

本轮使用合成源码验证执行与数据边界；真实模型对影响范围和新增用例的语义质量，
以及 Windows 成品操作体验，需要在对应环境验收，不能用无模型集成测试代替。
