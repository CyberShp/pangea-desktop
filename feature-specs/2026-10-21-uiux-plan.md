# PANGEA Desktop UI UX 整体开发修改方案

版本：1.1 · 2026-10-21  
交接对象：GPT-6.1-Sol 或其他开发 Agent  
交付状态：开发方案，尚未实施产品代码修改。

## 1. 执行目标和已定方向

本次改造解决三个问题：用户进入页面不知道先看哪里；信息密度与字体层级混乱；结果阅读、用例评审和下一步操作不连贯。以已认可的三张 V2 原型为视觉基线，覆盖整个桌面工作台，不只修改 TLS 示例页面。

必须实现的结果：用户进入页面后，能够依次辨认“当前处于什么状态、最需要关注什么、下一步能做什么”。首屏围绕一个主要内容区组织，每个页面状态至多一个实色主操作。

### 1.1 已确认的视觉决策

- 浅灰背景、白色内容面、深灰文字、克制的红色主色；减少满屏同权重卡片。
- 页面标题使用适度字重。删除标题上方重复面包屑、标题下方重复仓库／范围／Run 编号及宣传性说明。
- 分析详情页统一为“返回 + 任务标题 + 右侧任务信息”，下一行直接进入页签。仓库、范围、Run、时间等放进任务信息抽屉。
- 运行页突出当前业务单元和可读结果；概览突出待验证结论；用例页支持连续评审。
- 说明、证据、日志分层呈现。影响决策的错误、缺失条件与未解决事项必须直接可见。
- 单任务阶段用紧凑阶段条，多任务列表保持列表形态。此次不引入看板默认视图。

### 2.2 关键工程约束

- 插件源码的权威位置在 `dsh-pangea`，不能只修改 Desktop 中的打包副本。
- `dsh-pangea-companion` 的浏览器入口是 `lib/client.js`，由 `scripts/build-client.mjs` 生成。修改 `src/client.js` 后必须生成并检查产物，禁止手工只改 `lib`。
- 产品壳另有 `plugins/dsh-pangea/src/product-ui.css`，会由其构建脚本替换 `PRODUCT_UI_CSS` 占位符并进入产物；其中存在对壳层和 `.pangea-ui` 的后置覆盖。必须一并处理，不能只改 `installProductStyles()` 的早期样式。
- Companion 的构建器用 `SHARED` 列表和 `/* @inline-shared-modules */` 内联纯 ESM 模块。新增浏览器共享模块时必须登记；不得引入 Node API、未解析 import 或动态包依赖。
- 允许在现有 `src/`、`tests/`、`scripts/` 下增加本方案所需文件；不重构整个目录、不新增公共组件包、不替换构建链。
- 保留 source-first 与历史 Run 的阅读兼容；后端生命周期、分析结果、用户评审、执行结果分别建模。
- Agent 负责测试、开发构建、隔离环境和截图。推送、合并、正式发布按用户授权执行，不能把正常工程步骤交还用户。

## 3. 统一视觉与布局规范

### 3.1 设计变量

以 `plugins/dsh-pangea/src/product-ui.css` 作为产品视觉变量与共享组件样式的唯一权威源，由现有 `installProductStyles()`／构建注入链加载。清除 `src/client.js` 中冲突的硬编码覆盖；将 `.pangea-ui` 现有 `--bg/--text/--red` 等短变量映射到同一 `--pangea-*` 变量，避免维护两套值。各插件引用同一变量，避免分别维护红、绿、黑三种主按钮。以下是第一版确定值，视觉验收只允许围绕这些值作有理由的小幅调整。

| 类别 | 实现值 |
| --- | --- |
| 中文与拉丁字体 | `"Segoe UI", "Microsoft YaHei UI", "Microsoft YaHei", system-ui, sans-serif` |
| 代码字体 | `Consolas, "SFMono-Regular", ui-monospace, monospace` |
| 页面标题 | `26px / 34px`，字重 `600`；紧凑布局 `24px / 32px` |
| 区块标题 | `18px / 26px`，字重 `600` |
| 正文／表格／控件 | `14px / 22px`；长正文行高 `1.7` |
| 辅助信息 | `12px / 18px`，常规字重；核心操作和正文不能降到 10–12px |
| 画布／内容面 | `#F5F6F8` / `#FFFFFF` |
| 主文字／辅助文字 | `#20242B` / `#626B78` |
| 边框 | `#E1E5EB`；使用分组和留白优先于为每一行加卡片 |
| 主色／悬停／浅底 | `#B62836` / `#96212D` / `#FBF0F2` |
| 成功／注意 | `#26744D` / `#8C5A12`；用于状态，不作为第二套主操作色 |
| 间距 | `4 / 8 / 12 / 16 / 24 / 32px`；区块间 `24–32px`；行内 `8–12px` |
| 圆角 | 控件 `6px`，主要内容面 `10px`，避免大面积胶囊按钮 |
| 控件 | 常规高 `36px`；紧凑图标按钮至少 `32×32px`；明显键盘焦点 |

主要文字在对应底色上的对比度目标至少 4.5:1。禁用态之外，不通过过浅灰字制造层级。主要按钮只表达当前页面的主要任务；危险操作使用描边／文字样式及其既有确认流程。

### 3.2 共同页头

新增 `PageHeader`，统一以下参数：`title`、`onBack?`、`backLabel?`、`infoAction?`、`actions?`。页签作为紧邻其后的独立 `PageTabs`，不再分别拼接“面包屑 + hero + subtitle + meta”。

明确实现方式：在 `dsh-pangea/src/client.js` 定义组件，并通过现有产品服务新增只读 `ui` 属性，提供 `{ PageHeader, PageTabs, StatusBadge, EmptyState }`。Companion 和 Asset Catalog 从 `ctx.pangea.ui` 使用组件，不创建新依赖。与旧产品服务混用时，保留最小的语义化标题降级渲染；本次统一版本必须走共享组件。原有测试的 service stub 要补齐 `ui`，不要以缺失 mock 为由绕开共享组件。

- 分析详情标题优先使用任务标题；无任务的历史 Run 使用 Run 的业务目标；都缺失才用“分析详情”。不显示原型固定标题。
- 标题最多两行，超长完整标题在任务信息中可读；信息按钮保留文本“任务信息”，不能只留难理解图标。
- 抽屉内容：仓库、源码范围、资料及修订、场景、Run ID、开始／结束时间、工作流、交付状态；值缺失写“未记录”，不编造。
- 抽屉开关具有焦点管理、Esc 关闭、焦点归还。关闭后保持页签、滚动位置及当前选择。
- 表单字段的必要提示保留在字段附近；失败原因保留在状态区；深层页面返回目的地明确。这三类信息不能当“小字”整体隐藏。
- 已有工作区切换保留在产品壳，页头不重复展示 workspace root。

### 3.4 布局与滚动

- 主窗口基准为 `1380×900`，最小窗口为 `900×640`，保留现有 Electron 限制。
- 普通页面一个纵向内容滚动容器。标题和页签共用顶端区域；主体正常滚动，必要操作栏 sticky，不再叠多层页面滚动条。
- 运行／概览：内容容器可用宽度 ≥1000px 时，`minmax(0,1fr) 280px`，间距24px；不足1000px时，侧栏改为正文后折叠区。
- 用例：可用宽度 ≥1120px 才允许“列表260px + 正文 minmax(480px,1fr) + 来源240px”；850–1119px为“列表260px + 正文”，来源折叠到正文；不足850px为列表／详情切换，保留返回和前后导航。
- 响应式按**内容容器可用宽度**判断，打开 AI 助手后也必须触发布局变化；不能仅依赖浏览器 viewport 媒体查询。
- 图谱画布可以有局部平移缩放；会话列表／正文、用例列表／正文允许明确的独立阅读面板。不得形成同一内容连续三层嵌套滚动。
- 超宽窗口限制长正文阅读宽度约800px；表格和图谱可利用剩余空间。
- 页签窄窗口可横向滚动并自动露出当前页签，关键操作可见；不把正文缩到11px来塞内容。

| B14 | 各页面字体、主按钮颜色与小字号各自一套 | 三个插件的样式和 `styles` 对象；迁移至统一变量和组件 |

### 4.1 状态显示是一个投影，不能改变执行协议

扩展现有 `deriveRunPresentation(task,current,health)`，保持原字段兼容，增加明确的 `statusKey`、`statusLabel`、`tone`。所有概览／运行／列表徽标消费同一口径。状态读取错误由单独 `readState` 表达，不能覆盖保存的真实生命周期。

| 显示状态 | 依据 | 默认主要动作 |
| --- | --- | --- |
| 等待启动 | 尚未运行且具备启动条件 | 开始分析；条件缺失时转就近配置入口 |
| 准备中／分析中 | 服务端 reconciled lifecycle 或现有 execution state | 有可读产物：查看已生成结果；无产物：不强造主按钮 |
| 需要处理 | attention_required 或现有明确用户处理状态 | 处理待办；只能在真实允许时提供继续／交付 |
| 停止中 | stopping 且未获终态确认 | 停止中禁用态；可查看已有记录，不显示已停止或已完成 |
| 已停止 | confirmed stopped/cancelled | `can_resume=true` 才可继续分析；否则查看原因／结果 |
| 分析失败 | failed 或已核实失败状态 | 满足恢复条件时继续；否则查看失败原因；不得强行重启 |
| 已完成 | 明确 complete/completed | 有可评审用例则评审用例，否则查看已有报告／结果 |
| 部分交付 | 明确 partial_delivery | 查看已有结果；未解决事项仍可见 |
| 当前状态未知 | 本次读取失败或状态无法判定 | 重新读取；旧记录明确标“上次记录”，不能默认完成 |

优先使用当前 Run 的服务端校正状态，保留现有 Task/Run 身份隔离。旧轮询响应不能覆盖当前任务，stopping/failed 不得被旧 task.running 反转。过期状态下暂不根据旧 eligibility 触发写操作，先刷新；已有结果仍可阅读。

`publication`、`health`、运行状态、审查结论和实测结果是独立维度。读不到的数量显示“暂不可读”或未知，不显示0；草稿计数带“草稿”；PASS 审查不能显示为实测通过。

待处理统一谓词：`needs_attention` 与 `failed` 均属于“待处理”；组内保留真实状态标签。首页待办、统计数字和筛选结果共用该谓词。若当前任务列表数据分页，筛选与计数必须在同一全量集合／服务端查询上运行，不能一边全量统计、一边只筛当前页。

## 5. 页面行为规格

### 5.1 工作台、任务列表、概览和报告

工作台采用“当前需处理事项 → 最近任务 → 常用入口”顺序。首次无仓库时显示导入入口；有仓库无任务时显示新建入口；不展示全为0的统计大卡。

任务列表保留搜索与状态分组，行内只呈现标题、状态、业务进度、更新时间、必要操作。错误原因放展开详情；禁止每行同时放多个实色按钮。排序、筛选、返回位置保持稳定。

概览首屏顺序：任务页头与页签 → 状态／主要动作 → 至多3项重点结论 → 单行计数 → 流程与用例入口。超过3项提供“查看全部”；无结构化结论时显示“尚无可展示结论”及真实结果入口，不从用例预期或模型补写文本。

新增纯函数 `buildOverviewFindings({current,risks,notes})`，位置可放 Companion 新文件 `src/overview-findings.js` 并登记构建器。投影输出：`id,title,summary,kind,validationState,sourceRefs,caseRefs`。

- 优先级：工作流未解决事项 → 有明确证据关联的风险／分析note → 其余结构化分析结论。相同来源 ID 去重，同优先级稳定排序。
- 缺少来源的未解决事项仍展示，但标明“工作流待办”；不能包装为源码证据充分的发现。
- `validationState` 默认“待验证”；只有匹配到真实执行记录及正确用例身份才显示对应实测状态。采纳不改变验证状态。
- 摘要读取明确的 summary／narrative／trigger 等来源字段，完整原文通过来源入口打开。没有摘要就省略摘要，不借 expected_result 填充。
- 源码数量只用冻结源码快照，资料数量单独由资料清单计算；范围项数不能标成源码文件数。

报告页使用正文排版和章节导航，报告内容与完整原文保持可达。保留未解决事项、交付完整性、审查结论。移除外层重复状态卡和页面头上的冗长元信息，不修改原始报告内容。

### 5.2 运行过程和 Agent 会话

运行页首屏必须直接回答：当前在分析哪个业务对象、已保存多少结果、是否需要处理、可查看什么。主体只有一套状态描述，不重复叠 `RunExecutionSummary`。

- 阶段条读取 `current.workflow.steps`。若将其视觉归组为准备／规划／分析／复核／交付，`targeted_closure` 必须在复核组内明确显示“定向修正”；不能跳过失败、暂停、未解决阶段或伪造五步已完成。
- 默认选中当前活动阶段；用户手动选择历史阶段后轮询不抢回。页头明确区分“当前阶段”与“正在查看的阶段”。
- 进度只显示已接受单元／已知总单元；总数未知就显示“已完成N个单元”。分析单元比例不能叫整项任务百分比，不估算剩余时间。
- 当前关注最多3条，最近有效进展默认2条，展开可读全部。不能把最后一条任意工具输出当作业务结论。
- 右侧只展示可读产物及简洁范围；资料、源码、可评审用例分别统计。无产物时用明确空态。
- 错误、停止确认中、恢复阻断原因位于主体状态区。原始错误详情可折叠，但摘要和可采取的动作不能折叠。
- “执行详情与 Agent 会话”放次级区域；每条阶段任务能打开对应会话，并保留从全局查看所有会话的入口。

扩展 `AgentSessionsDialog` 参数：`initialSessionId?`、`initialUnitId?`、`initialActionId?`、`initialAttemptId?`，根据本Run会话元数据匹配。点击失败任务时传入该失败动作已知的session/action/attempt身份；精确session优先，否则同时限定action与attempt。不能仅凭同unit最新时间跳到另一次成功尝试。身份不足时展示限定后的候选列表并说明“请选择本次尝试”，不得声称已定位失败会话。无匹配显示“未找到关联会话”，不可打开另一Run的会话冒充。

会话列表首要显示业务单元名／角色／阶段／状态；ID和执行器细节进入“会话信息”。普通正文必须按安全Markdown渲染，至少正确呈现段落、标题、列表、加粗、行内代码和代码块；复用或补齐现有渲染能力，不能用整段pre／纯文本代替，HTML不执行。原始JSON和工具输入输出保持代码展示；工具调用默认只显示名称、状态、简短摘要，原始输入、输出、prompt默认折叠。工具失败摘要、未确认结束和录制故障外显。

第一版检索明确为“搜索已加载会话内容”，显示已加载范围与“加载更早记录”；不得把分页部分检索说成全量无结果。列表支持阶段／状态／业务单元筛选。保持最新输出在前、历史分页、取消请求和旧响应隔离；不改写任何会话记录。

### 5.3 新建分析和仓库导入

新建表单采用单主栏：分析目标 → 源码范围 → 可选资料 → 外部Agent及模型 → 开始分析。高级选项折叠；必填缺失与启动阻断信息放到相应字段和主按钮附近。

初始 `source_scope=[]`。提供目录／文件选择及“选择整个仓库”明确操作；用户选择整个仓库时才写入 `['.']`。保留可编辑路径输入供已有流程使用，但提交前必须校验实际路径存在和仓库边界。

新增范围选择与文件预览接口见第6.4节。选择完成后，确认区必须同时展示“整个仓库”或明确目录范围、命中文件全量去重数以及可展开的文件清单。例如“指定范围：nvmf_tcp/tls · 命中42个源码文件”，根目录则显著显示“整个仓库 · 命中N个源码文件”。42仅为示例，必须来自真实枚举；“已选1项范围”不能代替文件数。文件清单使用仓库相对完整路径并支持分页，计数不随分页改变。

预览处于扫描中、失败或部分完成时分别显示具体状态，不能把部分计数标成完整命中；正常启动要求完整有效的预览，0命中需调整范围。仓库或范围改变使旧预览立即失效。提交时重新校验文件集合，若与确认时不同则先更新预览，用户重新点击开始后才创建，不带着过期范围启动。资料选择不得改变源码范围；分析创建后用实际冻结快照记录最终文件数。新建与派生场景复用同一套范围预览，历史记录仅阅读时不强制迁移。

配置就绪分两路：分析任务依赖外部Agent；AI助手依赖其内部模型／API。内部API不可用不能阻止已具备条件的外部Agent分析；外部Agent不可用不能误报助手一定不可用。

### 5.4 用例列表和评审

列表过滤项：关键词、分析单元、用例类型、执行条件、评审状态；默认全部，按当前稳定分析单元顺序排列。执行条件来自 `readiness` 的 `ready / needs_setup / unclassified`，保留原始原因；无法识别的值显示未分类。

每页50条，结果数表示筛选后的全量数量。页码在筛选变化后回到第一页；轮询更新不无故重置筛选、当前用例、展开状态和滚动位置。

三个状态明确分离：

| 状态 | 用途 | 持久化规则 |
| --- | --- | --- |
| 当前查看 `activeCaseKey` | 正文阅读、上一条／下一条 | 页内导航状态；不产生评审决定 |
| 批量勾选 `selectedCaseKeys` | 复制、导出所选等批量操作 | 当前Run会话内；筛选变化保留并提示隐藏选择数量；切Run清空 |
| 评审决定 `reviewDecision` | 未评审／已采纳／暂不采纳／需重新评审 | 服务端独立保存；刷新和重启后可恢复 |

详情正文顺序固定：验证目标 → 执行条件与前置条件 → 操作步骤／逐步预期 → 观察点 → 清理动作。来源、关联流程和证据在安静侧栏／折叠区；原始记录继续可达。

“上一条／下一条”按进入详情时当前筛选顺序导航；不跨出筛选范围。轮询令当前对象不再匹配筛选时，保留当前阅读并提示，不突然跳页。到边界禁用按钮并显示 `当前位置 / 当前筛选数量`。

“采纳此用例”“暂不采纳”“撤销决定”都可逆。操作成功后留在当前用例，不自动跳下一条。保存中禁用重复提交；失败保留原决定并展示具体错误，不能显示已保存。源内容发生变化时已有决定进入“需重新评审”。

本页唯一实色主按钮为导出入口；采纳／暂不采纳使用描边或文字样式。导出弹窗明确范围和数量，规则见第6.3节。批量栏只在有勾选时出现并 sticky，正文留出相应底部空间。

### 5.5 流程、分支、图谱、风险与覆盖率

- 流程用主流程／子流程层级导航，主流程选中后能看到所属子流程；未知归属集中在“未归组”，不能丢弃。
- 分支检索、类型筛选、总数和分页在分支表上方常显。默认每页20条，完整原文单独折叠；不能只给前12条却不告知其余内容。
- 图谱提供适应画布、100%、放大、缩小、聚焦所选路径和全屏阅读。普通滚轮滚动页面；Ctrl+滚轮才缩放画布，按钮也可操作。
- 图形说明、变量明细和长文本移出图形 fit 的边界计算；选中对象详情放侧栏／下方折叠区。聚焦选中仅改变视图，不删除其他节点。
- 保持路径高亮、异常分支颗粒度、交互式SVG导出、历史图版本和源码跳转。不得为了画面简洁合并业务异常节点或替换成不可交互截图。
- 风险页突出触发条件、后果、待验证状态和证据，来源／等级依据仍可读；来源读取失败与无风险严格区分。
- 行为覆盖、用例质量说明默认折叠，异常／缺口摘要外显；保留当前已修复的折叠行为。
- 根据真实场景与已有 `riskApplicable` 等能力决定入口；三张原型未展示的风险、覆盖率、证据、复核和执行结果功能不能消失。

### 5.6 资产、设置、执行环境和助手

资产页沿用统一页头与表格密度；导入／解析状态、资料类型、修订和具体失败原因清楚可见。保留资产版本、选取、取消、重试和删除的现有语义。

设置按“分析执行器”“讨论助手模型”“其他已有配置”分组；前两组分别对应外部Agent与助手内部模型／API。每组分别检查连接与就绪，去掉泛化“配置API即可分析”的误导文案。连接失败显示对应配置项原因，不把所有错误塞进页面顶端。

执行环境保留主机／存储阵列字段和测试连接行为；密码不进入截图与日志。执行结果单独表达真实执行状态，不能复用分析完成或用例采纳标签。AI助手打开后不遮挡任务操作、用例正文或图谱工具栏。

## 6. 新增数据与接口契约

本节中的新文件、字段和API是待实施设计，不是已有能力。接口入口仍在 Companion 的 `src/index.js`，复用现有 same-origin 校验、数据根发现和 JSON／错误响应机制。

### 6.1 用例身份与用户决定

新增纯模块 `src/case-review-projection.js` 和服务模块 `src/case-review-store.js`。浏览器只内联纯模块；Node 文件系统和 `crypto` 留在服务模块。

持久身份为 `(解析后的dataRoot, run_id, caseKey)`。`caseKey` 优先 `projection_id`，否则非空且在当前Run唯一的 `test_case_id`；不可使用数组下标、标题、display_id。缺少稳定身份或同Run重复身份的用例可阅读和随“全部”导出，但不能保存评审／加入按身份选择的操作，界面说明原因。

`content_hash` 由服务端计算 SHA-256：对用例标题、类型、验证目标、前置条件、步骤与逐步预期、整体预期、观察点、清理动作、参数组合、执行条件及原因、关联来源ID／证据作规范JSON序列化后计算。对象键排序、数组保留语义顺序；不纳入读取时间、页面位置、轮询时间。定义 `content_hash_version=1`，后续算法改变不能默默继承旧决定。

第一版hash输入固定为以下字段的原始JSON值，缺失统一转null：`title,case_type,test_level,verification_goal,entry,preconditions,step_pairs,steps,expected_result,expected_results,observability,external_observations,cleanup,variants,execution_readiness,readiness,readiness_reason,missing_execution_conditions,unit_id,linked_risk_ids,linked_flow_ids,coverage_refs,evidence`。来源记录另取 `source_record.record_id/kind/body/evidence/relates_to`，不取外层执行状态和更新时间。不要把整条含轮询元信息的投影直接hash。

数据存放在 `<dataRoot>/.pangea/case-reviews/<runId>.json`，与作者分析结果分离。Run ID继续沿用现有合法性检查，不能拼接任意路径。示例：

```json
{
  "schema_version": 1,
  "content_hash_version": 1,
  "run_id": "run-example",
  "revision": 3,
  "decisions": {
    "unit-a/case-record-1": {
      "decision": "adopted",
      "content_hash": "sha256-value",
      "updated_at": "2026-10-21T12:00:00.000Z"
    }
  }
}
```

允许的持久决定：`adopted`、`excluded`；撤销决定删除该键。无记录读为 `unreviewed`；hash或hash版本不符时展示 `needs_recheck`，原决定留存但不计入有效采纳。新Run默认未评审，不从同名旧Run自动继承。

复用 `writeTaskStoreFile` 的原子写及 Windows rename 重试能力。按文件路径串行校验与写入，覆盖同进程两个store实例的并发冲突；禁止单靠每实例队列。通过revision做乐观并发控制。损坏JSON／未知schema必须返回可见错误并保留原文件，不能当空文件覆盖。此次不宣称支持多个独立服务进程同时写同一dataRoot；如现有部署允许该模式，需使用该项目已有跨进程锁后再开放写入。

### 6.2 评审接口

新增 `/api/pangea-companion/case-reviews`：

| 方法 | 请求 | 返回／行为 |
| --- | --- | --- |
| GET | query：`cwd,data_root,run_id` | `{status:'ok',run_id,revision,case_set_revision,cases:[{case_key,content_hash,review_status,decision,updated_at}],counts}`；只读，不创建文件 |
| POST | JSON：`cwd,data_root,run_id,expected_revision,case_key,expected_content_hash,decision` | decision为`adopted / excluded / unreviewed`；重读用例后校验身份／hash；原子保存并返回同形投影 |

`case_set_revision` 是当前用例身份及content_hash集合的稳定摘要，非时间戳。响应必须按请求Run隔离；切换Run时取消请求或丢弃旧响应。UI读取失败时仍可查看用例，采纳操作不可假成功。

错误：400非法参数，403来源／范围拒绝，404Run不存在，409revision或content_hash冲突，422缺失／重复用例身份或存储数据不受支持，500实际保存失败。409时刷新当前状态并提示“用例或评审已更新，请重新确认”，不能自动覆盖用户决定。

### 6.3 导出接口

保留现有 `GET /api/pangea-companion/export` 默认全部导出的兼容行为。新增同路径POST，用JSON承载大量选择，避免长URL：

```json
{
  "cwd": "workspace-path",
  "data_root": "data-root",
  "run_id": "run-example",
  "format": "xlsx",
  "scope": "selected",
  "case_keys": ["unit-a/case-record-1"],
  "case_set_revision": "current-set-hash",
  "review_revision": 3
}
```

| scope | 解析规则 |
| --- | --- |
| `all` | 当前Run全部可读取用例；不受页面筛选或勾选影响 |
| `filtered` | 客户端传当前筛选的**全量**case_keys，不仅当前分页；服务端按当前Run解析并校验集合版本 |
| `selected` | 客户端传勾选case_keys；显示并包含被筛选隐藏的勾选项数量 |
| `adopted` | 服务端根据最新评审存储选择有效adopted；忽略客户端伪造决定；检查review_revision |

POST要求当前 `case_set_revision`；adopted额外要求review_revision。格式非法返回400，Run不存在404，源内容／评审版本变化409，空范围或不可解析身份422。未知／重复／跨Run的key不可忽略，更不能回退为全部导出。数据读取失败时返回错误，不下载只有表头并显示成功。

成功仍返回文件二进制、正确content-type和文件名。`export.js`的格式化器保留纯函数；由路由构造过滤后的副本传入，不能原地修改Run。CSV／XLSX继续恰好八列：用例ID、标题、类型、前置条件、操作步骤、预期结果、观察点、清理动作（环境恢复）。保留参数组合在同一用例行、换行、BOM、完整文本；不增加审查元信息或原始记录列。

导出弹窗默认：有有效采纳时为“已采纳N条”，否则“全部N条”；始终允许用户明确切换范围。按钮显示实际选定范围与数量，0条禁用；内容变动时要求用户复核数量后再次导出。

### 6.4 源码范围选择与校验

复用 `/api/pangea-companion/repositories`，不改变既有无view GET与导入POST。

- 新增 GET `view=tree`，参数 `cwd,data_root,repository,path,cursor,limit`；path为仓库相对路径，默认`.`，limit默认100、最大200。返回 `{status:'ok',repository,path,entries:[{name,path,kind,selectable}],next_cursor,has_more}`。
- 新增 POST `action=validate-scope`，参数 `cwd,data_root,repository,source_scope`；返回 `{status:'ok',normalized_scope,selected_entry_count,entries:[{path,kind}]}`，失败返回逐项错误。路由先判断action，再保留旧导入分支。
- 新增 POST `action=preview-scope`，参数 `cwd,data_root,repository,source_scope,preview_id?,cursor?,limit?`；首次请求执行只读枚举，后续分页绑定同一个预览。返回 `{status:'ok',preview_id,preview_state,normalized_scope,is_entire_repository,matched_file_count,files:[{relative_path,size_bytes}],scope_revision,rules_revision,scanned_at,next_cursor,has_more,diagnostics}`。limit默认50、最大200；`matched_file_count`为全量去重结果，不是本页长度。`preview_state`为`complete/partial/error`；partial的计数不得标成完整命中，error计数为null。分页游标只用于该预览，失效或范围不匹配返回409并要求重新预览。
- 预览与创建冻结必须复用同一文件纳入／排除／递归／去重规则，不能将任意目录下的所有文件都算成源码。接手时在固定版本pangea-agent中定位实际冻结枚举，以`rg`搜索`source_scope`、`source_snapshot`、`file_count`；优先复用已有只读调用入口。若当前入口与创建绑在一起，只抽取／暴露该枚举的只读适配，不启动Run、不调用LLM、不复制源码快照。该最小适配属于UX-03必需范围；不能因接口缺失退化回只显示N项范围。
- 路径解析基于已注册仓库。tree的path只接受相对路径；validate-scope对相对路径按仓库根解析，绝对路径只在真实解析后位于该注册仓库内时转为相对路径。拒绝路径越界、NUL及外部符号链接；不能由客户端任意指定文件系统根。复用现有 `normalizeSourceScope` 的分隔符等规范，但不能仅凭绝对路径里含有同名仓库就放行；必须验证实际路径边界。
- Companion适配放 `src/repositories/scope.js`。目录树不读取全库文件内容；文件预览读取枚举必要的路径／元信息而不运行分析。隐藏不等于排除，不自行增设会改变实际分析范围的过滤规则。重叠目录、同一路径重复选择按实际冻结规则去重。
- 创建输入新增`scope_preview_id`与`expected_scope_revision`，在启动Agent前校验所属仓库、规范范围、规则版本和当前命中文件集合。`scope_revision`绑定仓库、范围、规则版本及排序后的完整路径集合，不能只绑定文件数量。集合变化返回409与重新预览提示，不创建Run；0命中或非完整预览返回422。范围参数错误400；读取失败给具体路径诊断，不能回退父目录或整个仓库。
- 用同一冻结输入准备步骤校验确认过的集合并完成冻结；若该步骤内集合再次变化，创建应报范围变化且不得启动Agent。预览数是创建前文件集合计数，不宣称源码内容已锁定；创建后的实际`source_snapshot`仍为最终输入依据。固定fixture下必须验证预览路径集合与真实冻结路径集合相同，不能仅比较数量。

### 8.2 真实界面验收

尺寸覆盖：1380×900、1280×720、1920×1080、900×640；Windows 100%、125%、150%缩放。每个核心页面至少验证助手关闭／打开两种状态，重点检查内容容器变窄后的重排。

截图至少包含：运行中／失败／停止中，概览完成／部分交付，用例列表／详情／导出，流程与图谱，工作台／新建／任务列表／资产／设置。每张记录视口、缩放、fixture与页面状态，不使用真实凭据。

可用性快速验收：由未参与实现的人在不预先讲解页面的情况下，回答“现在什么状态、最需要看什么、下一步点哪里”。三张核心页均应能在约5秒内给出正确答案；如仍需解释，优先调整层级而非继续加说明小字。这是验收目标，不能声称已完成用户实验。

键盘验收覆盖Tab顺序、明显焦点、按钮可操作、弹窗焦点陷阱、Esc关闭和焦点归还。状态不能只靠颜色区分。

## 9. 不能回退的已有行为

- 用例详情返回列表后，滚动位置与展开状态恢复。
- 行为覆盖默认折叠，阶段产物有独立间距。
- Agent会话最新输出在前，历史分页和请求隔离正确。
- 流程路径选择与高亮、交互式SVG导出、源码依据跳转。
- 不可读数据不会伪装成0条，终态耗时不会继续增长，过期同步不会装成实时状态。
- 既有停止确认、恢复 eligibility、Job身份、checkpoint及报告发布语义。
- CSV／XLSX严格八列、参数组合仍属于原用例、不混入审查记录。

不得因视觉改造删除历史／legacy结果阅读、执行环境、风险、覆盖率、证据或复核入口。原型只表达层级，不代表删功能清单。
